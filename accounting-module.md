# Accounting Module Specification
### Carpentry Workshop Management System — AppSmith + Supabase

---

## Overview

This module handles all financial record-keeping for the workshop: supplier invoices, project expenses, weekly payroll, cost tracking per site, and monthly profit-and-loss summaries. It is built on two tools:

- **Supabase** — the database that stores all records
- **AppSmith** — the interface the accountant uses to view, enter, and export data

No coding knowledge is required to use this module. All data entry and reporting is done through the AppSmith pages described in Section 8.

---

## 1. Database Tables (Supabase)

These tables are created once by a developer. The accountant does not interact with them directly.

### 1.1 `supplier_invoices`

Stores every invoice received from a supplier.

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Auto-generated unique ID |
| `invoice_number` | Text | Invoice number as printed on the document |
| `supplier_name` | Text | Name of the supplier |
| `amount` | Numeric | Total invoice amount (ZAR) |
| `due_date` | Date | Payment due date |
| `payment_status` | Text | One of: `unpaid`, `paid`, `overdue` |
| `purchase_order_id` | UUID | Links to the related purchase order (optional) |
| `attachment_url` | Text | URL of the uploaded invoice PDF or image |
| `notes` | Text | Any additional notes |
| `created_at` | Timestamp | Auto-set when the record is created |

**Automatic overdue flagging:** A scheduled database job runs every night and sets `payment_status = 'overdue'` on any invoice where the due date has passed and payment has not been recorded. The accountant does not need to do anything — overdue invoices flag themselves.

---

### 1.2 `expenses`

Logs every expense incurred during operations.

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Auto-generated unique ID |
| `expense_date` | Date | Date the expense was incurred |
| `category` | Text | One of: `materials`, `labour`, `transport`, `miscellaneous` |
| `description` | Text | Brief description of what was purchased or spent |
| `amount` | Numeric | Amount spent (ZAR) |
| `site_id` | UUID | Links to the site or project this expense belongs to |
| `purchase_order_id` | UUID | Links to a purchase order (optional) |
| `recorded_by` | UUID | The user who entered the record |
| `created_at` | Timestamp | Auto-set when the record is created |

---

### 1.3 `payroll`

One record per worker per month, generated by the accountant during payroll processing.

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Auto-generated unique ID |
| `worker_id` | UUID | Links to the worker's profile |
| `month` | Date | First day of the payroll month (e.g. 2024-11-01) |
| `total_hours` | Numeric | Sum of hours from daily reports for the month |
| `hourly_rate` | Numeric | Worker's rate at time of calculation (copied from their profile) |
| `gross_pay` | Numeric | `total_hours × hourly_rate` |
| `status` | Text | One of: `draft`, `reviewed`, `paid` |
| `paid_date` | Date | Date payment was made (filled in by accountant) |
| `created_at` | Timestamp | Auto-set when the record is created |

**Source data for calculation:**
- `daily_reports` — contains each worker's hours per day
- `profiles` — contains each worker's hourly rate

---

### 1.4 `sites` (shared reference table)

| Column | Description |
|---|---|
| `id` | Unique site ID |
| `site_name` | Name of the site or project |
| `start_date` | Project start date |
| `status` | Active or completed |

## 2. Supplier Invoices

### What it does
- Records every invoice received from a supplier
- Tracks whether it has been paid, is still outstanding, or has gone overdue
- Allows the accountant to upload the invoice document (PDF or photo)
- Links invoices to their originating purchase orders for easy cross-reference

### Key rules
- An invoice starts as **unpaid** when first entered
- An invoice becomes **overdue** automatically if the due date passes without payment
- An invoice is marked **paid** manually by the accountant after payment is confirmed
- Overdue invoices are highlighted in red in the invoices list
- Uploaded documents are stored securely and can be opened at any time

### Accountant actions
1. Add a new invoice using the invoice form
2. Upload the invoice document
3. Mark an invoice as paid once payment has been made
4. Filter the list by status: unpaid / paid / overdue
5. Search by supplier name or invoice number
6. Export the invoice list to CSV

---

## 3. Expense Tracking

### What it does
- Logs every workshop expense with a date, category, and amount
- Assigns each expense to a specific site or project
- Links to a purchase order where applicable
- Provides running totals per site and per category

### Categories

| Category | Used for |
|---|---|
| Materials | Timber, hardware, adhesives, finishes, consumables |
| Labour | Subcontractor payments, casual labour not on the payroll |
| Transport | Delivery fees, fuel, vehicle hire |
| Miscellaneous | Any expense that does not fit the above categories |

### Key rules
- Every expense must have a date, category, amount, and site
- Linking to a purchase order is optional but strongly recommended for materials
- All expenses flow automatically into the Cost per Site summary

### Accountant actions
1. Add a new expense using the expense form
2. Filter expenses by site, category, or date range
3. View running totals per site and per category
4. Export expenses to CSV

---

## 4. Payroll Calculation

### What it does
- Pulls hours worked from daily reports for a selected month
- Multiplies each worker's hours by their hourly rate from their profile
- Generates a draft payroll for the accountant to review and approve
- Allows the accountant to mark each worker's pay as confirmed and then paid
- Provides a payslip summary for each worker

### Calculation

```
Gross Pay = Total Hours Worked (this month) × Hourly Rate (from worker profile)
```

### Step-by-step process

1. The accountant selects the month (e.g. November 2024)
2. The system reads all daily report entries for that month and totals hours per worker
3. The system fetches each worker's hourly rate from their profile
4. A draft payroll line is created for each worker showing: name, total hours, rate, and gross pay
5. The accountant reviews each line, checking for any errors or unusual hours
6. The accountant clicks **Confirm Payroll** to lock the month's figures
7. After payments are made, the accountant marks each worker as **Paid** and enters the payment date
8. A payslip summary is available to view or export per worker

### Key rules
- Payroll is locked once confirmed — it cannot be edited after that point
- If a worker has no hours for a month, they appear with zero hours rather than being hidden
- The hourly rate is captured at the time of calculation — if the rate changes later, historical payroll records are not affected

## 5. Cost per Project / Site

### What it does
Gives a clear view of how much each site has cost, broken down by expense type, with both a running total and a month-by-month breakdown.

### What is included

| Cost type | Source |
|---|---|
| Materials | Expenses logged under the Materials category |
| Labour | Expenses logged under the Labour category |
| Transport | Expenses logged under the Transport category |
| Miscellaneous | Expenses logged under the Miscellaneous category |
| Payroll labour | Worker payroll costs attributed to this site (if hours are logged per site) |

> **Note:** If workers do not log hours against specific sites in their daily reports, payroll costs will appear as a workshop-wide total rather than broken down per site.

### Display format
- **Running total** — a single figure showing the full cost of the site from start to present
- **Monthly breakdown** — a table showing what was spent each month since the site began
- A bar chart showing the split between cost categories

---

## 6. Monthly P&L Summary

### What it does
Provides a one-page monthly snapshot of the workshop's financial position: what came in, what went out, and the net result.

### Summary structure

| Line item | Source |
|---|---|
| **Total Income** | Client invoices raised this month (if tracked in the system) |
| **Total Expenses** | Sum of all expense records for the month |
| **Total Payroll** | Sum of all confirmed payroll gross pay for the month |
| **Total Cost** | Expenses + Payroll |
| **Net Position** | Total Income − Total Cost |

> If client invoicing is not yet tracked in this system, the Income line will show as zero, and the Net Position will reflect total outgoings only.

### Display format
- A summary card at the top showing the Net Position (green if positive, red if negative)
- A table showing each line item with a comparison to the previous month
- A month selector to view any past month

## 7. CSV Export

The accountant can export any of the following to a CSV file for use in external accounting software (Pastel, Xero, QuickBooks, or similar):

| Export | Columns included |
|---|---|
| **Invoices** | Invoice number, supplier, amount, due date, status, notes |
| **Expenses** | Date, category, description, amount, site name, purchase order |
| **Payroll** | Worker name, month, total hours, hourly rate, gross pay, status, paid date |
| **Cost per Site** | Site name, category, total cost |
| **Monthly Summary** | Month, income, expenses, payroll, net position |

### How to export
1. Navigate to the relevant page
2. Apply any filters you want (date range, site, status, etc.)
3. Click **Export to CSV**
4. The file downloads automatically to your computer

## 8. AppSmith — Page-by-Page Build Instructions

The following instructions are for the developer building the AppSmith interface. Each section covers one page.

---

### Page 1: Invoices

**Purpose:** View, add, and manage all supplier invoices.

**Layout:**

```
[ + Add Invoice ]  [ Filter: Status ▼ ]  [ Search: supplier or invoice # ]  [ Export CSV ]

┌──────────────────────────────────────────────────────────────────────────────┐
│ Invoice #  │ Supplier     │ Amount  │ Due Date   │ Status      │ Actions      │
│ INV-001    │ Timber Co    │ R 4,200 │ 2024-11-15 │ [OVERDUE]   │ View  Mark Paid │
│ INV-002    │ Hardware Hub │ R 1,800 │ 2024-11-30 │ [unpaid]    │ View  Mark Paid │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Build steps:**

1. Create a new AppSmith page called **Invoices**
2. Add a **Table widget** bound to this query:
   ```sql
   SELECT id, invoice_number, supplier_name, amount, due_date, payment_status
   FROM supplier_invoices
   ORDER BY due_date ASC;
   ```
3. Set row colour: rows where `payment_status = 'overdue'` show a red background
4. Add a **Search input** widget — filter the table by `supplier_name` or `invoice_number` as the user types
5. Add a **Status dropdown** filter (options: All / Unpaid / Paid / Overdue) that filters the table
6. Add a **"+ Add Invoice" button** that opens a Modal widget containing a form with:
   - Invoice Number (Text Input)
   - Supplier Name (Text Input)
   - Amount (Number Input)
   - Due Date (Date Picker)
   - Purchase Order (Dropdown — populated from the `purchase_orders` table)
   - Notes (Text Area)
   - Attachment Upload (FilePicker widget — uploads file to Supabase Storage bucket `invoice-attachments` and saves the returned URL)
   - **Submit button**: runs an insert query into `supplier_invoices` then closes the modal and refreshes the table
7. Add a **"Mark Paid" button** in each table row — runs an update query setting `payment_status = 'paid'` and recording today's date
8. Add an **"Export CSV" button** — uses AppSmith's built-in download utility to export the current filtered table view

---

### Page 2: Expenses

**Purpose:** Log and review all workshop expenses by category and site.

**Layout:**

```
[ + Add Expense ]  [ Filter: Site ▼ ]  [ Filter: Category ▼ ]  [ Date Range ]  [ Export CSV ]

┌──────────────────────────────────────────────────────────────────────────────┐
│ Date       │ Category   │ Description          │ Amount  │ Site        │ Edit │
│ 2024-11-01 │ Materials  │ Timber — Site A      │ R 3,500 │ Greenfield  │ Edit │
│ 2024-11-03 │ Transport  │ Delivery fee         │ R 450   │ Greenfield  │ Edit │
└──────────────────────────────────────────────────────────────────────────────┘

Totals:  Materials: R 3,500  |  Transport: R 450  |  Total: R 3,950
```

**Build steps:**

1. Create a new AppSmith page called **Expenses**
2. Add a **Table widget** bound to:
   ```sql
   SELECT e.id, e.expense_date, e.category, e.description, e.amount,
          s.site_name, e.purchase_order_id
   FROM expenses e
   LEFT JOIN sites s ON e.site_id = s.id
   ORDER BY e.expense_date DESC;
   ```
3. Add a **Site dropdown** filter — populated from the `sites` table; filters the table when changed
4. Add a **Category dropdown** filter — hardcoded options: Materials, Labour, Transport, Miscellaneous
5. Add a **Date Range picker** — two date inputs (From / To) that filter by `expense_date`
6. Add a **"+ Add Expense" button** opening a Modal with:
   - Date (Date Picker, default: today)
   - Category (Dropdown — Materials, Labour, Transport, Miscellaneous)
   - Description (Text Input)
   - Amount (Number Input)
   - Site (Dropdown — from `sites` table)
   - Purchase Order (Dropdown — optional, from `purchase_orders` table)
   - **Submit button**: inserts into `expenses` then closes the modal and refreshes the table
7. Add **running total Text widgets** below the table — one per category, each bound to a `SUM(amount)` query filtered by that category and the current filters
8. Add an **"Export CSV" button**

---

### Page 3: Payroll Calculator

**Purpose:** Generate, review, and confirm monthly payroll for all workers.

**Layout:**

```
Month: [ November 2024 ▼ ]   [ Generate Payroll ]   [ Confirm & Lock ]   [ Export CSV ]

┌──────────────────────────────────────────────────────────────────────────────┐
│ Worker Name   │ Total Hours │ Hourly Rate │ Gross Pay  │ Status  │ Actions   │
│ John Dlamini  │ 168         │ R 85/hr     │ R 14,280   │ draft   │ Mark Paid │
│ Sipho Nkosi   │ 152         │ R 85/hr     │ R 12,920   │ draft   │ Mark Paid │
└──────────────────────────────────────────────────────────────────────────────┘

Total payroll this month:  R 27,200
```

**Build steps:**

1. Create a new AppSmith page called **Payroll Calculator**
2. Add a **Month selector** — a Dropdown showing the last 24 months (formatted as "November 2024")
3. Add a **"Generate Payroll" button** that runs the following query and inserts results into the `payroll` table:
   ```sql
   SELECT dr.worker_id,
          p.full_name,
          p.hourly_rate,
          SUM(dr.hours_worked)                    AS total_hours,
          SUM(dr.hours_worked) * p.hourly_rate    AS gross_pay
   FROM daily_reports dr
   JOIN profiles p ON dr.worker_id = p.id
   WHERE DATE_TRUNC('month', dr.report_date) = DATE_TRUNC('month', :selected_month::date)
   GROUP BY dr.worker_id, p.full_name, p.hourly_rate;
   ```
   For each result row, insert a record into `payroll` with `status = 'draft'`. Skip workers who already have a payroll record for this month.
4. Display results in a **Table widget** bound to:
   ```sql
   SELECT pr.id, p.full_name, pr.total_hours, pr.hourly_rate, pr.gross_pay, pr.status, pr.paid_date
   FROM payroll pr
   JOIN profiles p ON pr.worker_id = p.id
   WHERE DATE_TRUNC('month', pr.month) = DATE_TRUNC('month', :selected_month::date)
   ORDER BY p.full_name;
   ```
5. Add a **"Confirm & Lock" button** — updates all `draft` payroll records for the selected month to `status = 'reviewed'`
6. Add a **"Mark Paid" button** per row — updates that record to `status = 'paid'` and sets `paid_date` to today
7. Add a **total gross pay Text widget** at the bottom: `SELECT SUM(gross_pay) FROM payroll WHERE month = :selected_month`
8. Add a **Payslip modal** — clicking a worker's name opens a Modal showing their payslip: name, month, total hours, hourly rate, gross pay, and status
9. Add an **"Export CSV" button**

### Page 4: Cost per Site

**Purpose:** View the total cost of each site, broken down by category and month.

**Layout:**

```
Site: [ Greenfield Residence ▼ ]

Running total to date:  R 48,750

Monthly Breakdown:
┌───────────────────────────────────────────────────────────────────────────┐
│ Month      │ Materials │ Labour  │ Transport │ Misc  │ Total              │
│ Oct 2024   │ R 15,000  │ R 8,000 │ R 1,200   │ R 500 │ R 24,700          │
│ Nov 2024   │ R 18,000  │ R 5,500 │ R 550     │ R 0   │ R 24,050          │
└───────────────────────────────────────────────────────────────────────────┘

[Bar chart: monthly cost by category]
```

**Build steps:**

1. Create a new AppSmith page called **Cost per Site**
2. Add a **Site dropdown** — populated from the `sites` table
3. Add a **"Running Total" Stat Box widget** bound to:
   ```sql
   SELECT SUM(amount) AS total FROM expenses WHERE site_id = :selected_site_id;
   ```
4. Add a **Table widget** for the monthly breakdown:
   ```sql
   SELECT
     TO_CHAR(DATE_TRUNC('month', expense_date), 'Mon YYYY') AS month,
     SUM(CASE WHEN category = 'materials'     THEN amount ELSE 0 END) AS materials,
     SUM(CASE WHEN category = 'labour'        THEN amount ELSE 0 END) AS labour,
     SUM(CASE WHEN category = 'transport'     THEN amount ELSE 0 END) AS transport,
     SUM(CASE WHEN category = 'miscellaneous' THEN amount ELSE 0 END) AS misc,
     SUM(amount) AS total
   FROM expenses
   WHERE site_id = :selected_site_id
   GROUP BY DATE_TRUNC('month', expense_date)
   ORDER BY DATE_TRUNC('month', expense_date) DESC;
   ```
5. Add a **Chart widget** (Bar chart) using the monthly breakdown data — series: Materials, Labour, Transport, Misc; x-axis: month
6. Add an **"Export CSV" button**

### Page 5: Monthly Summary

**Purpose:** One-page monthly financial snapshot comparing income, expenses, payroll, and net position.

**Layout:**

```
Month: [ November 2024 ▼ ]

┌──────────────────────────────────────────────────────────┐
│  Net Position this month:  − R 39,950                    │
└──────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────────┐
│ Line item       │ This month   │ Last month   │ Change            │
│ Total Income    │ R 0          │ R 0          │ —                 │
│ Total Expenses  │ R 12,750     │ R 15,400     │ ▼ R 2,650         │
│ Total Payroll   │ R 27,200     │ R 24,100     │ ▲ R 3,100         │
│ Total Cost      │ R 39,950     │ R 39,500     │ ▲ R 450           │
│ Net Position    │ − R 39,950   │ − R 39,500   │                   │
└───────────────────────────────────────────────────────────────────┘
```

**Build steps:**

1. Create a new AppSmith page called **Monthly Summary**
2. Add a **Month selector** — Dropdown showing the last 24 months
3. Add a **"Net Position" Stat Box widget** at the top — text colour set dynamically: green if the value is ≥ 0, red if negative
4. Run the following queries for the selected month and the previous month:
   - **Expenses:** `SELECT SUM(amount) FROM expenses WHERE DATE_TRUNC('month', expense_date) = :month`
   - **Payroll:** `SELECT SUM(gross_pay) FROM payroll WHERE DATE_TRUNC('month', month) = :month AND status != 'draft'`
   - **Income:** Set to 0 until client invoicing is tracked in this system
5. Build the summary table using an AppSmith JS Object that constructs the rows from the query results:
   ```javascript
   const thisExp   = queryExpensesThisMonth.data[0].sum || 0;
   const lastExp   = queryExpensesLastMonth.data[0].sum || 0;
   const thisPay   = queryPayrollThisMonth.data[0].sum  || 0;
   const lastPay   = queryPayrollLastMonth.data[0].sum  || 0;
   const thisCost  = thisExp + thisPay;
   const lastCost  = lastExp + lastPay;

   return [
     { item: "Total Income",   thisMonth: 0,         lastMonth: 0,         change: "—" },
     { item: "Total Expenses", thisMonth: thisExp,   lastMonth: lastExp,   change: lastExp   - thisExp   },
     { item: "Total Payroll",  thisMonth: thisPay,   lastMonth: lastPay,   change: lastPay   - thisPay   },
     { item: "Total Cost",     thisMonth: thisCost,  lastMonth: lastCost,  change: lastCost  - thisCost  },
     { item: "Net Position",   thisMonth: -thisCost, lastMonth: -lastCost, change: "" },
   ];
   ```
6. Format the **Change column** with arrow indicators (▲ increase, ▼ decrease)
7. Add an **"Export CSV" button** that exports the summary table

## 10. Developer Setup Checklist

Before handing the module over to the accountant, complete the following:

- [ ] Create all Supabase tables as defined in Section 1 (`supplier_invoices`, `expenses`, `payroll`)
- [ ] Confirm `sites`, `daily_reports`, and `profiles` tables exist with the expected columns
- [ ] Enable Supabase Storage and create a bucket called `invoice-attachments`
- [ ] Set the bucket policy to allow authenticated users to upload and read files
- [ ] Create and schedule the overdue invoice update job using `pg_cron`:
  ```sql
  SELECT cron.schedule(
    'flag-overdue-invoices',
    '1 0 * * *',   -- runs at 00:01 every day
    $$
      UPDATE supplier_invoices
      SET payment_status = 'overdue'
      WHERE due_date < CURRENT_DATE
        AND payment_status = 'unpaid';
    $$
  );
  ```
- [ ] Connect AppSmith to Supabase using the Supabase datasource plugin (enter your project URL and service role key)
- [ ] Build all five pages as described in Section 8
- [ ] Configure roles and assign the accountant user to the **Accountant** role
- [ ] Test payroll generation with at least one month of `daily_reports` data before go-live
